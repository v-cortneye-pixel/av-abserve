### 4.3 `data-output.json` — **NOT deleted (intentionally tracked)**

The initial cleanup pass removed `av-observe-main/data-output.json` based
on observing that:

- `apps/av-daily-update/app.js#saveDataOutput()` writes to
  `${dataDir}/data-output.json` where `dataDir` is `./.ignore` (local)
  or `./.data` (CI) — **never** the repo root.
- The committed copy has only one commit in history (the initial upload),
  suggesting nothing keeps it fresh.

That deletion was reverted on review. The
`apps/av-daily-update/README.md` documents the file as
**"Tracked in Git for historical reference and CI artifact storage"** —
which is a deliberate statement of intent.

The contradiction between code and documentation is now itself an open
item:

- **Option A — documentation is right, code is wrong.** Some
  out-of-repo CI step (GitLab pipeline?) copies `${dataDir}/data-output.json`
  up to `av-observe-main/data-output.json` and commits it. If so, the
  in-app writer is fine; just verify the CI step exists and is healthy.
- **Option B — code is right, documentation is aspirational.** The CI
  copy step was planned but never built. The committed file is therefore
  stale, but harmless. Either implement the copy step or update the
  README to drop the "tracked in Git" claim.
- **Option C — change `saveDataOutput()` to write directly to the repo
  root** (`${repoRoot}/av-observe-main/data-output.json`) in CI, and let
  the existing CI commit it as part of the pipeline.

Pick one. None require touching this branch.
